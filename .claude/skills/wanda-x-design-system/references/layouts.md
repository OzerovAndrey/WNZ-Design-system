Проблеми:
1. **Лейаути на застарілих обгортках**: Gamehall зібраний з `.Desktop page (Debricate)` / `.Mobile page (Debricate)`, хоча в ДС є `Page/Desktop` і `Page/Mobile`.
2. **Компоненти живуть у лейаутах**: на Profile + десятки наборів (`content profile balances`, `Betting history item`, `Loyalty points history item [Current]`…). На Homepage + — `stores`, `stories bg`.
3. **4+ іконкові системи** одночасно: `BR / Default / …`, `icons / general / …`, `icon / status / …`, `menu / …`, голі `close`, `cancel`, `chevron-down`, `flame`, `goblet`.
4. **EXAMPLE-компоненти** у продакшн-макетах: `Game thumbs - EXAMPLE`, `homepage/slider/mob/back-EXAMPLE`.
5. Сотні фреймів `Frame 123…`, фрейми без auto layout.

## Правила збирання лейауту

1. Корінь екрана — інстанс `Page/Desktop` або `Page/Mobile` з `Breakpoint`; ніяких `(Debricate)`.
2. Усе, що є в ДС, — інстансом з ДС. Нема в ДС — спершу компонент (через DoD), потім лейаут.
3. Продуктові компоненти (фічі) — у продуктовому файлі, не в лейауті і не в ДС.
4. Іконки — тільки з `Static — Icons` (`icons.md`); swap тільки через `↳ 💠` властивості.
5. Auto layout на всіх рівнях; секції — `Section` компонент; ширини — `FILL`.
6. Тексти — тільки зі стилем; кольори — тільки токени.
7. Брейкпоінти з `Breakpoints`: `3xs, 2xs, sm, md` (mobile), `xl, 2xl, 3xl` (desktop).
8. Перевірка лейауту в обох темах (`MB`, `XON`) перед передачею.

## Порядок очистки лейаутів
Спершу ДС (компоненти до 🟢) → потім заміна `(Debricate)` обгорток → потім swap іконок на єдину бібліотеку → потім винос локальних наборів з лейаутів → потім неймінг/AL.
