# Як ми працюємо з Андреєм — домовленості та пастки (читати ПЕРЕД будь-якою роботою)

Зібрано 2026-10-22 за підсумком великої сесії (Chips, Datepicker, Filter & Sorting, Gamehall, List, Profile-menu). Якщо щось тут суперечить старішому файлу скілу — правильно те, що тут.

## 1. Режим роботи
- Андрей дає посилання на компонент / Section і завдання. **Змінювати Figma — тільки коли просить** («зроби», «прив'яжи», «поправ»). Питання «чому / що думаєш / як краще» — спершу відповідь, без змін.
- **Оригінали не видаляти.** Якщо робимо нову збірку — поруч; старі набори складаємо в Section `Originals — <назва> (не використовувати)`. Видаляти варіант / компонент — тільки на прямий запит, і тільки після перевірки, що інстансів 0 (або Андрей сказав).
- Після кожної дії — скріншот (`get_screenshot`) і коротка відповідь українською: що зроблено, що змінилось візуально, що питання. Не обіцяти того, чого не перевірено.
- Не підміняти відсутній токен «схожим» наявним без погодження (урок Datepicker). Якщо точного немає — запропонувати варіанти або **створити** новий (alias / component), назвавши, що візуально зміниться.

## 2. Токени — робочий цикл (JSON-handoff)
1. Андрей створює **свою бренчу** в Token Studio і дає повні JSON сетів: зазвичай `alias` + `component` для MB, потім для XON (4 файли). Перевірити `product` у alias (`MB`/`XON`), щоб не переплутати.
2. Claude **редагує саме ці JSON** (python: load → зміни → dump `indent=2, ensure_ascii=False`) і **diff-перевіряє** проти оригіналу: показати `+` / `-` / `~`. Жодних інших змін.
3. Віддає готові файли (`SendUserFile`), Андрей вставляє в Token Studio і робить Export.
4. **Не писати в storage Token Studio напряму** — sync з GitHub перезапише.
5. Прив'язка в Figma: якщо змінних ще немає (Export не зроблено) — **створити змінні з тими самими назвами** в колекції `Product` (alias на ті самі alias-змінні, обидва режими, правильні scopes) і прив'язати + токен на шар (plugin data `tokens`).
6. **Export з бренчі, де немає наших токенів, ВИДАЛЯЄ створені вручну змінні** → прив'язки стають «мертвими». Лікування: створити змінні знову і перепривʼязати **за plugin data `tokens` на шарах** (скрипт: для кожного вузла читати ключі `tokens`, мапити `height/itemSpacing/padding*/borderRadius/fill` на змінну з назвою `token.replace(/\./g,'/')`). Тому: перед Export просити Андрея вставити ВСІ останні JSON.

## 3. Правила токенів (рішення Андрея)
- **Компонентні токени посилаються тільки на alias, не на core.** Якщо потрібного значення в alias немає — додати alias-токен (так з'явились `semantic.fill.subtle` = `{core.content.a8}`, `semantic.fill.subtle-invert` = `{core.white.500}` alpha 0.1 через `$extensions.studio.tokens.modify`, `semantic.fill.active`, `border-radius.global.xs` = `{border-radius.core.100}`).
- **Текст, іконки, шеврони — глобальні `semantic.text.*` / `semantic.icon.*` напряму**, без `contextual.<c>.text/icon`. Компонентні токени — для заливок, обведень, розмірів, радіусів. Для іконок на темному — `semantic.text.default-invert.*` (групи icon-invert немає).
- **Падінги: `padding-h`, `padding-v`** (не `padding-horizontal`). Асиметричні — `padding-left`.
- **Висоту рядкових компонентів задаємо size-токеном на `height`** (`profile-menu.item.height` = `{size.600}` = 48, `subitem.height` = `{size.400}` = 32), **без вертикальних падінгів**. Залишаємо тільки горизонтальний падінг.
- **Квадратні елементи** (іконки, буллети) — `lockAspectRatio()` + токен лише на `height` (`icon-size`, `bullet.size`).
- Зайві токени не плодимо: gap 0 / прозора заливка / значення, що задається в інстансі — без токена.
- Інвертовані кольори: `contextual.<c>.inverted.*` / `contextual.<c>.<part>.inverted.*` (так назвав Андрей: `contextual.chips.inverted`, `contextual.profile-menu.item.inverted.fill.active`).
- Типографіка — стилі `text/*` (`text.md`, `text.md-stronger`, `text.sm-strong` …), токен `typography` на шарі.

## 4. Структура компонентів (рішення Андрея)
- **Без text-властивостей** (`✏️ Label`) — текст міняють в інстансі.
- **Дефолтні тексти — `Label`, дефолтна іконка — `plus`** (Static — Icons), у списках за замовчуванням **3** пункти.
- **Без зайвих обгорток** (`Header`, `Frame 123`, `text wrap`) — діти прямо в корені; обгортка лишається лише там, де без неї не скласти (рядок над слотом в `State=Open`).
- **Не плодити варіанти**: якщо Desktop/Mobile відрізняються лише gap/шириною — один універсальний компонент зі слотом, різницю задають в інстансі.
- **Стани — логічно**: неактивний не може бути відкритим → `State = Default | Active | Open` (Open = активний + розкритий), а не `Active × Open`.
- **Слоти** (`createSlot`) для списків пунктів; preferred values — набір пункту. Під-компонент у слоті (`Profile-menu/Subitem`) лишаємо — він дає стан Active і Badge.
- **Inverted — лише там, де компонент реально стоїть на темному фоні** (перевірити макети: фон-предок під інстансами). Не «для кожного за замовчуванням». XON уже темний через alias — Inverted ≠ бренд.
- Section: основний компонент першим, під-компоненти під ним; Section названа як основний компонент.
- Іконки — тільки `Static — Icons` (перевіряти `search_design_system` з `includeLibraryKeys` Static).

## 5. Аналіз використань (перед будь-якою оптимізацією)
- Для кожного набору й варіанта: `getInstancesAsync()` → сторінка, власник (компонент/фрейм), вкладеність, override-и (тексти, іконки, boolean-и), фон-предок (світлий/темний).
- **`getInstancesAsync` НЕ повертає пункти всередині слотів інстансів** — їх шукати через інстанси контейнера (`menu.findOne(SLOT).children`).
- Сторінки вантажаться ліниво: перед `findOne` всередині інстансу з іншої сторінки — `await page.loadAsync()`, інакше `null`.
- Інстанси на сторінці `?` (без PAGE-предка) — залишки видалених вузлів, ігнорувати.
- Вкладені копії (instance всередині instance іншого компонента) оновлюються від мейна — міняти лише верхній рівень; список верхніх інстансів збирати **до** змін (після видалення старого вузла id вкладених стають недійсними).

## 6. Пастки Plugin API (перевірено)
- **Перенесення шарів у мейні (прибрати обгортку) скидає override-и інстансів** (текст, swap іконки, колір іконки) — шлях шару змінився. Перед зміною записати override-и всіх інстансів (у `figma.root` plugin data) → змінити → повернути.
- **Зміна дефолтного тексту в мейні перепише інстанси, де текст збігався з дефолтом** (там немає override) — так `Balances` став `Label`. Перед зміною дефолтів зафіксувати тексти.
- **`clone()` варіанта губить `componentPropertyReferences`** (Chevron/Tag перестали керуватись boolean-ами, шар Tag зник) і перетворює SLOT на FRAME. Після клонування: відновити посилання, видалити FRAME і створити слот заново з `slotContentId` = ключ наявної властивості.
- Клон варіанта з'являється на сторінці, а не в наборі → `set.appendChild(clone)`.
- `figma.createSlot` не існує — `componentNode.createSlot()`; другий варіант ділить властивість: `slot.componentPropertyReferences = {slotContentId: key}` і видалити дубль-властивість.
- Paint з прив'язаною змінною: задавати **fallback-колір = реальне значення змінної** (не чорний) — інакше скріншот/рендер показує чорний.
- Скріншот компонента-власника може бути застарілим кешем — перевіряти на іншому вузлі (батьківський попап) або даними.
- Прихований шар в інстансі не видно через `findOne` — дивитися `componentProperties`.
- Помилка посеред `use_figma` = скрипт відкочується повністю; `return` раніше — зміни до нього лишаються.
- Темний фон з **мертвою змінною** (fallback колір іншого бренду) — це поломка макета, а не привід для Inverted.
