# Оформлення Section на сторінці компонента

Еталон — Section `Anchor` (сторінка `↳ Anchor`, node `78314:307705`).

## Стиль Section

| Властивість | Значення |
|---|---|
| Назва | = назва компонента (`Anchor`, `Badge`); заголовка-тексту всередині немає |
| Заливка | **сіра `#BBBBBB`**, opacity 100% |
| Обведення | чорне `#000000` 10%, 1 px, суцільне |
| Радіус | 2 |

**Чому сіра, а не біла:** у кожного компонента є `Inverted=True` (світлий контент для темного фону, див. `naming.md` → Inverted). На білому фоні інвертована версія не читається, на темному — звичайна. Нейтральний сірий показує обидві одночасно.

Заливка й обведення Section — службові (документація сторінки), тому hex тут **не дефект**: аудит Section не перевіряє, токени на неї не ставимо.

Рамку самого `COMPONENT_SET` (фіолетовий пунктир) не чіпаємо — це дефолт Figma.

## Вміст
- Одна Section на компонент.
- Всередині тільки main-компоненти / набори. Ні нотаток, ні тестових інстансів, ні превʼю-фреймів.
- Варіанти всередині набору: **16 px** від країв набору і **16 px** між варіантами (як в `Anchor/Item`).

## Розкладка
- Стовпчиком.
- **80 px** від країв Section до вмісту (зверху, знизу, зліва, справа).
- **80 px** між компонентами по вертикалі.
- **Основний компонент — завжди перший** (зверху): той, що використовується в дизайні (`Anchor`, `Datepicker`). Під-компоненти, які його наповнюють (`Anchor/Item`, `Datepicker/Date` …), — під ним (рішення Андрея 2026-10-22).
- Розмір Section — по вмісту: `80 + max(width) + 80` × `80 + Σheight + 80·(n−1) + 80`.

## Поруч з оригіналом
Section стоїть праворуч від оригіналу, поки старий компонент не переведено в `Deprecated`.

## Скрипт (Plugin API)
```js
const section = figma.createSection();
section.name = '<Component>';
section.fills = [{ type: 'SOLID', color: { r: 187/255, g: 187/255, b: 187/255 } }];
section.strokes = [{ type: 'SOLID', color: { r: 0, g: 0, b: 0 }, opacity: 0.1 }];
section.strokeWeight = 1;
section.cornerRadius = 2;
```
